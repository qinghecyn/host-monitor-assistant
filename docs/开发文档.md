## 一、这个项目是什么

实时查看 Linux 主机运行状态的监控工具，数据通过 **SSH 只读采集**。
一套采集代码适用于 OpenWrt / iStoreOS、软路由、Ubuntu/Debian 服务器、KVM 虚拟机、物理机。

三个交付形态：

| 形态 | 产物 | 说明 |
|---|---|---|
| 桌面版 | `主机监控小助手_0.2.3_x64-setup.exe` | Tauri 壳 + 内嵌 Python 后端，装完即用 |
| 手机版 | `主机监控小助手_手机版_0.2.3.apk` | Chaquopy 内嵌同一套 Python 后端，手机直连被监控机 |
| 浏览器版 | 源码运行 / `启动监控.bat` | 局域网多设备看，需要机器上有 Python |

核心设计约束（所有组件都围绕它们）：

1. **SSH 只读**：远端只执行 `cat`/`awk`/`df`/`docker ps` 这类只读命令，不在目标机写任何文件；
   SSH 凭据只在后端，不进前端、不写日志、不回传接口。
2. **逐段容错**：任何一个采集项失败只影响自己那一字段（显示 "—"），绝不拖垮整帧。
3. **速率在本地算**：远端只吐累计值（CPU jiffies、网卡字节），本地用帧内时间戳做差值，
   远端 sleep 抖动、脚本偶尔变慢都不影响准确性。
4. **零依赖目标机**：目标机只要有 SSH + POSIX sh（busybox 即可）+ `df -P -k`；
   Docker/风扇都是"有就采集、没有就静默省略"的可选段。

## 四、采集协议与数据帧

远端脚本每秒输出**一行**，段用 `|` 分隔、条目用 `;` 分隔、字段用 `,` 分隔：

```
T=<unix秒>                     帧时间戳（速率差值的基准）
U=<uptime整秒>
L=<load1>,<load5>,<load15>
CPU=t:usr,nic,sys,idle,iow,irq,sirq,steal;0:...;1:...   累计 jiffies
MEM=<总KB>,<可用KB>,<Buffers>,<Cached+SReclaimable>
DSK=<挂载点>,<总KB>,<可用KB>,<累计读KB>,<累计写KB>,<块设备名>;...  排除 tmpfs/overlay 等伪挂载（/ 例外保留）
NET=<网卡>,<rx累计字节>,<tx累计字节>,<operstate>;...   beta2.3：排除 lo 后的全部接口
TMP=<类型>,<毫摄氏度>;...                      /sys/class/thermal 遍历
FAN=<名称>,<RPM>;...          beta2.1          /sys/class/hwmon fan*_input；无风扇则整段省略
OS=<PRETTY_NAME>
DKS=none|down|ok,<运行数>,<总数>               beta2.0 Docker 段；没装 docker 则整段省略
DKP=<id12位>,<名称>,<镜像>,<state>,<状态详情>;...
DKST=<id>,<cpu%>,<已用>/<上限>,<内存%>,<网络IO>,<块IO>;...   仅运行中的容器
```

结构化帧（JSON，前端拿到的就是它）：

```jsonc
{
  "ts": 1793297872.1, "status": "online",
  "os": {"pretty_name": "..."}, "uptime_s": 86400,
  "cpu":  {"percent": 23.5, "cores": 8, "per_core": [...], "load": [...]},
  "memory": {"total_kb": ..., "available_kb": ..., "available_percent": 96.1},
  "temperatures": [{"zone": "...", "type": "...", "temp_c": 45.5}],
  "fans": [{"name": "it8620:fan1", "rpm": 1033}],          // beta2.1；rpm=0 有效
  "disks": [{"mount": "/", "total_kb": ..., "available_kb": ...}],
  "network": [{"iface": "eth0", "rx_kbps": 1.4, "tx_kbps": 8.2, ...}],
  "docker": {"daemon": "ok|down|none", "running": 2, "total": 3,
             "containers": [{"id": "...", "name": "...", "state": "running",
                             "cpu_percent": 3.21, "mem_used": "45.2MiB", ...}]}
}
```

两个容易踩的设计点：

- **Docker 段按时间缓存**：`docker stats --no-stream` 本身要采样 1~2 秒，脚本里容器列表每 5s、
  stats 每 30s 刷新一次，其余帧复用缓存值；刷新导致的那一帧变慢由时间戳差值兜底。
  stats 用 `timeout 15` 兜底防 daemon 卡死。DKP↔DKST 用 12 位容器 ID 对齐合并。
- **历史缓冲不存 docker**（容器列表大且不画曲线，只随 latest / 实时 metrics 推送）；
  fans 很小，历史里保留。

## 五、HTTP API 与 WebSocket（速览）

鉴权：`POST /api/login` 换 token（内存 24h）；桌面/手机壳用 `POST /api/login/desktop`
+ 壳注入的一次性令牌（环境变量 `XMM_DESKTOP_TOKEN`）免登录；登录接口有 0.4s 延迟防爆破。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/ping | 就绪探测（壳启动轮询），无需鉴权 |
| POST | /api/login · /api/login/desktop | 登录 |
| GET | /api/snapshot | 完整快照（targets + data{latest,history,alerts} + probes + notify）|
| GET/PUT | /api/config | 脱敏读取 / 白名单更新（alerts、collect、auth、notify、history、probes）|
| GET/POST/PUT/DELETE | /api/targets… | 多目标 CRUD，改完即时生效并原子写回 config.toml |
| POST | /api/targets/test | 试连一台机器（不保存），返回耗时/系统/核数 |
| GET | /api/history?host&metric&minutes | beta2.2：历史查询，自动降采样 ≤800 点 |
| GET/POST/PUT/DELETE | /api/probes… | beta2.2：拨测 CRUD（写 config + 热重载探针）|
| POST | /api/notify/test | beta2.2：向指定通道发测试消息 `{channel}` |
| GET/POST | /api/service | beta2.2：Windows 服务状态 / `{action: install\|uninstall\|start\|stop}` |
| POST | /api/shutdown | 停止后端进程（桌面壳/手机 App 跟着退出）|
| WS | /ws | 连接后 10s 内发 `{"type":"auth","token":...}`；随后收 hello/metrics/status/alert/probe/targets |

config.toml 结构：`[server] listen_host/listen_port`、`[auth] username/password`、
`[collect] interval_s/history_minutes`、`[alerts] temp_c/mem_available_percent/root_free_gb`、
`[notify] enabled/dedup_minutes/quiet_start/quiet_end/serverchan_key/telegram_*/smtp_*/webhook_url/heartbeat_minutes`、
`[history] keep_days`、`[targets.<名称>] host/port/username/password|password_env|private_key/host_key_policy/label/note`、
`[probes.<名称>] type(tcp\|http\|ping)/host/port/path/expect/interval_s/timeout_s/fail_threshold`。
界面增删改 = 原子写回该文件（保留 .bak），文件永远是当前真相。
**凭据字段（sendkey/token/密码/webhook）只在 PUT 时写入，GET 一律以 `has_xxx` 布尔回显。**

## 六、桌面版打包（Windows exe）

```bat
set PATH=%USERPROFILE%\.cargo\bin;%PATH%
packaging\build_all.bat
```

等价步骤（手工执行时按此顺序）：

```bat
:: 1. 编译独立后端（服务模式/浏览器版也用这个 exe）
cargo build --release --manifest-path rs\xmm\Cargo.toml --bin xmm-server

:: 2. 摆资源：web/ + 两个 exe（tauri.conf.json 的 bundle.resources 引用）
xcopy /E /I /Y web shell\tauri\src-tauri\resources\web
copy rs\xmm\target\release\xmm-server.exe shell\tauri\src-tauri\resources\bin\
copy packaging\winsw\xiaozhushou-service.exe shell\tauri\src-tauri\resources\bin\

:: 3. 出 NSIS 安装包（需要 Rust 工具链 + Node）
cd shell\tauri && npx --yes @tauri-apps/cli@2 build
```

> 旧链路（PyInstaller 冻结 `server/` + `collector/` 成 124MB sidecar）已废弃；
> 只有打手机版 APK 时才需要 Python 环境。

- 产物：`shell/tauri/src-tauri/target/release/bundle/nsis/主机监控小助手_<版本>_x64-setup.exe`
- **改版本号要同步的位置**：`rs/xmm/src/lib.rs VERSION`、`rs/xmm/src/bin/xmm-server.rs` 横幅、
  `server/api.py VERSION` + `server/app.py snapshot_payload`（Python 版/手机版）、
  `web/index.html`（两处 ver 徽标）、`shell/tauri/src-tauri/tauri.conf.json + Cargo.toml + main.rs`、
  `web/js/app.js` 回退值、`run.py` 横幅、`build_all.bat`
- Tauri 壳行为：单实例锁（回环端口 47823）→ 挑空闲端口 + 生成一次性令牌 →
  **本进程内起 tokio runtime 跑 axum 后端** → 轮询 /api/ping → 开窗口 + 注入
  `window.__XMM_BOOTSTRAP__`；关窗口 = 收进托盘，界面"退出" = `/api/shutdown` 结束整个进程
- 资源：`resources/web/`（前端静态文件）、`resources/bin/xmm-server.exe`（服务模式）、
  `resources/bin/xiaozhushou-service.exe`（WinSW 包装器）

构建环境要求：Rust stable（x86_64-pc-windows-gnu）、Node 18+。**不需要 Python。**

## 七、手机版打包（Android APK，Chaquopy）

`dist\主机监控小助手_手机版_0.2.3.apk`（beta2.3 交付，versionCode 10）。**后端就是同一套 Python 代码**——
PyInstaller 出不了安卓程序，安卓也不允许 APK 拉起子进程，所以用
[Chaquopy](https://chaquo.com)（Gradle 插件）在 APK 内嵌 CPython 3.13 直接跑 `server/`。

```
shell/chaquopy-app/
├─ app/build.gradle            chaquopy 17.2 + AGP 8.7；server/ collector/ web/ 以
│                              setSrcDirs + include 白名单只读引用原项目（源码零改动）
├─ app/src/main/python/android_main.py   唯一新增的 Python：
│                              127.0.0.1:8787 起 uvicorn；设 XMM_DESKTOP_TOKEN；
│                              给 index.html 注入 __XMM_BOOTSTRAP__（与桌面壳同机制）
├─ app/src/main/java/.../MainActivity.java  WebView + 轮询 /api/ping 后加载；返回键=后台
└─ app/monitor.keystore        沿用旧版签名（applicationId 相同，可覆盖升级）
```

依赖处理：Chaquopy 轮子仓库没有 pydantic-core（Rust），所以锁 `fastapi<0.116 + pydantic v1`
（均纯 Python）；cryptography/cffi/bcrypt 用 Chaquopy 官方安卓轮子（无需 NDK）。

构建（需 JDK 21 + Android SDK + buildPython `build\py313`）：

```bat
cd shell\chaquopy-app
set JAVA_HOME=C:\Program Files\Eclipse Adoptium\jdk-21.0.13.9-hotspot
gradlew.bat assembleRelease
:: 产物 app\build\outputs\apk\release\app-release.apk
```

已知边界：后端只监听 127.0.0.1（App 内 WebView 访问）；监控只在 App 存活期间运行
（未做前台服务常驻）；配置存在手机私有目录，与电脑版各自独立。
`shell/capacitor/` 是旧版遗留（只连后端地址的浏览器壳），已被取代，仅存档。

换启动图标：把新图放 `D:\xiaozhushou_monitor\logo.png`，跑 `scripts/gen_app_icons.py`
（需 Pillow），重新打包即可——脚本会生成自适应前景（62% 安全区）+ 传统密度全套 PNG。

  事件走推送管线；结果落盘进趋势页

## 九、开发与测试工作流

```bash
# 单元/端到端测试（51 例）
cargo test --manifest-path rs\xmm\Cargo.toml

# 源码运行
python run.py --mock                # 内置模拟数据（含 Docker/风扇样例），不连 SSH
python run.py --mock --mock-dropout # 演示"离线保留数据"
python run.py --config config.toml  # 真实目标

# 采集脚本语法检查（busybox 兼容性）
wsl sh -n collector/remote/collect.sh
```

约定：

- 后端所有日志走 `logging`，桌面版写 `<data-dir>/server.log`
- `tests/fixtures/wsl_sample.txt` 是真实采集样本，存在即自动做回归，不存在跳过
- 改行协议时三处同步：`collect.sh`、`parser.py`、`docs/协议与数据格式.md`，并补 parser 用例

### 加一个新采集项的固定套路（以风扇为例）

1. `collector/remote/collect.sh`：加一个 `xxx_info()` 函数（POSIX sh、只读、失败静默省略），
   在 `emit_once` 里追加 `|XXX=$v`，文件头注释更新协议
2. `collector/parser.py`：帧默认值 + 解析分支 + `_parse_xxx()` 静态方法（逐条容错，
   坏条目跳过不坏整段），补 3 类用例：正常帧 / 缺段+坏段 / 边界值
3. `web/index.html`：加卡片骨架；`web/js/app.js`：`renderAll()` 加渲染分支并把卡片 id
   加进显隐控制数组
4. `collector/mock.py`：加模拟数据，`--mock` 模式即可先看 UI
5. 真机验证 → 版本号全套 → 打包（见第六节）
