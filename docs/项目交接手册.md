## 1. 这是个什么项目

**主机监控小助手**：通过 SSH 只读采集 Linux 主机（OpenWrt/iStoreOS 软路由、服务器、虚拟机）的
CPU / 内存 / 温度 / 风扇 / 磁盘 / **全部网卡** / Docker 容器负载，配上告警推送、SQLite 历史、
服务拨测、Windows 服务。FastAPI + 原生 JS，打包成免装 Python 的桌面 App 和独立安卓 App。

**唯一真相是核心源码 `server/`、`collector/`、`web/`**：桌面壳（Tauri）和手机壳（Chaquopy）
都只读引用这三块，绝不为某一端改核心结构。`build/`、`dist/`、`shell/*/build/`、
`shell/tauri/src-tauri/resources/server-dist/` 都是**生成物**，别手改。

### 数据流（每秒一帧）

```
目标机                          本机                                 展示
/proc、/sys、df、docker           collector/ssh_client.py              web/js/app.js
    │  sh -s 从 stdin 注入脚本        │  asyncssh 长连接/断线重连          │  HTTP 快照 + WS
    ▼                                ▼                                  ▼
collect.sh ──一行行协议──▶ parser.py ──结构化帧──▶ server/app.py ──▶ 卡片 / 折线图
（远端只吐累计值）          （本地差值算速率）      （历史/告警/多目标）    server/store.py 落盘
```

- 远端脚本 **不写目标机任何文件**，只用 `cat`/`awk`/`df`/`docker ps` 这类只读命令。
- 段之间 `|`、条目 `;`、字段 `,`；某段采集失败就整段省略，解析端逐段 try/except。
- SSH 凭据只在后端，不进前端、不回传接口、不写日志、不要写进任何文档。

## 3. 多网卡链路：改了什么、为什么（最关键）

### 两个根因

1. **旧前端只取 `network[0]`**：`/proc/net/dev` 第一行通常是 `eth0`，
   所以 `eth1`、`br-lan`、`utun`、`docker0` 即使采集到了也永远不显示。
2. **busybox awk 的 `%d` 是 32 位有符号**：累计字节超过 `2^31` 就变负数。
   修复前实测 `eth0 total=-2097152.0 KB`，导致累计流量错、差值速率变 0/负、主网卡选错。

### 现在每一层怎么做

| 层 | 文件 | 做法 |
|---|---|---|
| 采集 | `collector/remote/collect.sh` | `NET=<iface>,<rx字节>,<tx字节>,<operstate>;...`，输出除 `lo` 外**全部**接口；`operstate` 读 `/sys/class/net/<iface>/operstate`，读不到留空；**所有累计值一律 `%.0f`**，绝不改回 `%d` |
| 解析 | `collector/parser.py` | `_parse_net()` 解析 4 字段（兼容旧 3 字段）、拒绝负计数、给每帧**恰好一个**接口标 `primary=True`；`pick_primary_network()` 口径：先排除 `down`，再优先 `eth/en/wl/br-/lan/wan/bond/pppoe/ap` 开头的真实接口，再按累计流量取最大 |
| 历史 | `server/store.py` | `net.rx_kbps/tx_kbps` 优先用帧里的 `primary` 标记，旧帧回退 `pick_primary_network()`，不再取 `network[0]` |
| 前端 | `web/js/app.js` | `pickPrimaryNet()` 优先读后端 `primary`，兜底同口径；卡片头写「主网卡（共 N 个接口 · M 个有流量）」；**逐行渲染全部网卡**：主网卡置顶打「主」、`down` 标「未连接」并置灰删除线、零流量置灰、按活跃+累计流量+名称排序 |
| 样式 | `web/css/main.css` | `.netlist` `max-height: 260px`（手机 220px）+ 内部滚动，19 张网卡不会撑爆页面 |
| 模拟数据 | `collector/mock.py` | 4 张卡：`eth0`/`eth1`/`br-lan`(主)/`tunl0`(零流量)，方便 `--mock` 直接验收 |

> **口径统一是这次的关键**：主网卡由后端算一次，前端和 SQLite 历史共用同一标记，
> 避免「曲线画 eth0、大数字显示 br-lan」这种漂移。

### 顺手修掉的遗留 bug

`collector/ssh_client.py` 的一次性采集原来写 `sh -s --once`，`--once` 被 sh 当成自己的选项吃掉，
`$1` 为空 → 远端脚本进入无限循环。现在模块级常量：

```python
ONESHOT_CMD = "sh -s -- --once"     # 必须有 `--`
```

`tests/test_beta23_regression.py` 会用真实 `sh` 验证 `$1` 传参、真实 `collect.sh` 只输出一行就退出，
以及 >2^31 累计值、负计数拒绝、旧 3 字段兼容。**别把这个常量改回去。**

## 4. 安卓全面屏与侧滑返回（beta2.3）

`shell/chaquopy-app/app/src/main/java/com/xiaozhushou/monitor/MainActivity.java`：

- `applyEdgeToEdge()`：透明状态栏/导航栏，API 29+ 关对比度遮罩，API 30+ `setDecorFitsSystemWindows(false)`
  + 浅色系统图标，低版本用 `SYSTEM_UI_FLAG_LAYOUT_*` 兜底。
- `applySystemBarInsets()`：给 `android.R.id.content` 设置 top/bottom/left/right padding，
  API 30+ 用 `WindowInsets.Type.systemBars() | displayCutout() | ime()`，
  覆盖状态栏、刘海、手势条、横屏刘海和输入法。
- 返回手势：API 33+ `OnBackInvokedDispatcher` 注册 `OnBackInvokedCallback`；
  API <33 用 `onBackPressed()`；**两条路都只进 `handleBack()`**（`onKeyDown` 里的重复处理已删除，
  否则一次侧滑会触发两次）。
- 分层返回靠前端 `web/js/app.js` 的 `window.__xmmHandleBack()`：
  服务器抽屉 → `manager.back()`（表单先退回列表再关抽屉）→ 设置 / 拨测 / 历史逐层关 →
  返回 `default` 时壳才 `moveTaskToBack(true)` 退后台（监控继续跑）。
- `AndroidManifest.xml`：Activity 加 `windowSoftInputMode="adjustResize"`、
  `windowLayoutInDisplayCutoutMode="shortEdges"`，保留 `enableOnBackInvokedCallback="true"`。

### 安卓 17 打开闪退修复（2026-11-06，versionCode 10）

真机：小米 `24122RKC7C` / HyperOS / **Android 17（API 37）**。用户报「打开闪退」，
`build/adb_diagnose.sh` 抓到崩溃栈：

```text
Caused by: java.lang.NullPointerException:
  Attempt to invoke virtual method 'WindowInsetsController DecorView.getWindowInsetsController()'
  on a null object reference
    at com.android.internal.policy.PhoneWindow.getInsetsController(PhoneWindow.java:4235)
    at com.xiaozhushou.monitor.MainActivity.applyEdgeToEdge(MainActivity.java:82)
    at com.xiaozhushou.monitor.MainActivity.onCreate(MainActivity.java:45)
```

**根因**：`applyEdgeToEdge()` 在 `setContentView()` **之前**调用
`getWindow().getInsetsController()`。Android 17 的 `PhoneWindow` 此时 DecorView 还没创建，
方法内部直接解引用 `mDecor` 抛 NPE；旧版系统只是返回 `null`，代码里判了空所以没暴露。

**修复（MainActivity.java，四层防护）**：

1. `setContentView(web)` 提前到所有 Window / WindowInsets 操作之前，DecorView 一定存在；
2. 用 `getWindow().getDecorView().getWindowInsetsController()` 取 controller，
   不经过 `PhoneWindow` 的 `mDecor` 解引用（`getDecorView()` 本身会确保 Decor 已安装）；
3. `applyEdgeToEdge()` / `applySystemBarInsets()` / `registerBackCallback()` 整体包
   `try/catch (Throwable)`，任何 OEM ROM 差异只降级成系统默认窗口，**绝不让 onCreate 抛异常**；
4. 新建 `BackInvokedCompat.java` 隔离 API 33 的 `OnBackInvokedCallback` / `OnBackInvokedDispatcher`，
   `MainActivity` 本体不再引用这两个类，避免 Android 12/13（API 31/32）类验证阶段 VerifyError。

`versionCode` 从 9 升到 **10**（同 `versionName 0.2.3`），否则已装 9 的机器无法覆盖升级。

**真机复测（Android 17）**：`adb install -r` → 冷启动 → 进程存活（PID 11412）、栈顶
`com.xiaozhushou.monitor/.MainActivity`、logcat 无本 App 的 `FATAL EXCEPTION`；
Chaquopy 的 `libpython3.13.so` 等 native 库全部加载成功；
`adb forward tcp:8787 tcp:8787` 后 `/api/ping` 返回 `beta2.3`，首页注入了 `__XMM_BOOTSTRAP__`；
`input keyevent 4` 返回后进程仍在（`moveTaskToBack` 而非崩溃）；
真机截图 `docs/shots/android17-fixed.png` 显示状态栏与底部手势条都不遮挡内容。
原始崩溃日志 `build/adb_crash_before_fix.log`，修复后日志 `build/adb_crash.log`。
诊断脚本：`build/adb_diagnose.sh`。

> 兼容范围 Android 12～17：本次只有 Android 17 实机可测；12/13 通过第 4 点的类隔离做静态保证，
> 14/15/16 走的是同一套 API 30+ 分支，逻辑一致。

## 8. 打包踩过的坑（别再踩）

1. **`packaging/build_all.bat` 是 GBK + CRLF 编码**。Windows cmd 按系统代码页（936）解析 .bat，
   用 UTF-8 保存会让中文 echo 变成乱码甚至被拆成错误命令。改这个文件时**保持 GBK + CRLF**，
   或者把提示全改成 ASCII。文件里**不要**放 `chcp 65001`（cmd 会预读行，反而乱码）。
2. **沙箱/CI 里的批量删除保护**：`build_all.bat` 会 `rd /s /q` 旧的 `server-dist`（100+ 文件），
   PyInstaller 也会删旧的 `dist-sidecar/xiaozhushou-server`，在受控环境里会被拦。
   绕法：先把旧目录 **重命名**成 `.prev`，再让工具新建；或按第 7 节分步命令手动跑。
   本次因此留下 `build/dist-sidecar/xiaozhushou-server.prev` 与
   `shell/tauri/src-tauri/resources/server-dist.prev`（各约 62MB，均为旧 0.2.2 构建副本），
   确认新版稳定后可手动删除，不影响运行。
3. **`pause` 会卡住自动化**：已改成 `if not "%XMM_NO_PAUSE%"=="1" pause`，双击运行仍会停。
4. **Rust 不在 PATH**：不加 `%USERPROFILE%\.cargo\bin` 会在第 4 步失败。
5. **`versionCode` 必须递增**：0.2.3 是 10（0.2.2 是 8），不递增手机覆盖安装不升级。
6. **WSL 在当前环境被安全策略禁用**，跑 `sh -n` / 脚本冒烟请用 Git Bash 自带的 `sh`；
   多网卡真实验证只能靠 192.168.1.100（本机 WSL 只有 eth0）。
7. **`dist/` 里旧 0.2.2 产物先留着**，确认新版可用再清理；别拿旧 `dist/xiaozhushou-server`
   或 `shell/*/build` 里的旧代码判断功能。
8. **项目不是 git 仓库**，没有 `git diff` / 回滚；改文件前先备份或读一遍。

---

9. **安卓系统栏 API 必须在 `setContentView()` 之后调用**：`getWindow().getInsetsController()`
   在 Android 17 上会因 DecorView 未创建直接 NPE 闪退（不是返回 null）。详见第 4 节闪退修复。
   全面屏适配这类「锦上添花」的代码一律 try/catch 降级，别让它决定 App 能不能启动。

10. **`aapt dump badging` 不能传中文路径**（Git Bash 下报 `Illegal byte sequence` /
    `ERROR: dump failed because no AndroidManifest.xml found`）。验证 APK 版本请用英文路径的
    `shell/chaquopy-app/app/build/outputs/apk/release/app-release.apk`，或先 `cp` 成 ASCII 文件名；
    `adb install -r` 对中文路径没有这个问题（手机里 `dumpsys package | grep versionCode` 也能验）。

## 12. Rust 后端（2026-11-09 新增）

### 为什么

Python sidecar（PyInstaller）内存 74.6MB、解压后 124MB，主要是解释器 + FastAPI/asyncssh 的固定成本。
Rust 版把后端并入 Tauri 进程：真实 SSH 采集时 34MB 工作集 / 7.5MB 私有内存，无子进程。

### 代码在哪

`rs/xmm/`：`parser.rs`（行协议）、`ssh.rs`（russh 长连接/重连/指纹/oneshot/测试连接）、
`state.rs`（采集器生命周期 + 目标 CRUD + 快照 + 告警边沿）、`api.rs`（axum 路由/WS/静态资源）、
`config.rs`、`store.rs`、`notify.rs`、`probes.rs`、`mock.rs`、`service.rs`、`auth.rs`、`alerts.rs`、`history.rs`。
HTTP/WS/JSON 契约与 `server/api.py` 一一对应，`web/` 前端零改动。

### 踩过的坑（务必记住）

1. **不要用 aws-lc-rs**：`russh` 默认 feature 会拉 BoringSSL C 源码，Windows 上编译 20 分钟起步。
   已在 `Cargo.toml` 关掉默认 feature、改用 `ring`；HTTP/SMTP 走 native-tls（SChannel）。
2. **`russh` 与 `russh-keys` 的密钥类型不是同一个 crate**：russh 0.54 用的是
   `internal-russh-forked-ssh-key`，直接用 `russh::keys::*`，别再单独引 `russh-keys`。
3. **std 的锁不可重入**：`snapshot_payload` 持 `collectors` 锁再调 `meta()`、
   `on_frame` 与 `meta()` 的加锁顺序相反，都造成过界面卡死（请求超时）。
   现在统一"用完即出块"，全项目保持 cfg → collectors → histories/alerts 的顺序。
4. **axum handler 里的 `RwLock` 守卫不能跨 await**：否则 future 非 Send，
   报错会伪装成 `Handler is not satisfied`，很难认。用块把守卫限制住。
5. **Windows 服务**：桌面 exe 是 GUI 程序，服务必须跑同目录的 `xmm-server.exe`（打包时带上）。
