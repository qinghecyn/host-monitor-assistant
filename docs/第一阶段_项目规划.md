## 一、技术选型（结论 + 理由）

| 层 | 选型 | 理由 |
|---|---|---|
| 后端语言 | Python 3.10+ | 需求建议；`asyncssh`/`fastapi` 生态成熟 |
| SSH 长连接 | **asyncssh** | 纯异步，与 FastAPI 同一个事件循环，无回调地狱；对 Dropbear（OpenWrt）兼容良好 |
| Web 框架 | **FastAPI + uvicorn** | 自带 WebSocket 支持，一个进程同时提供 HTTP + WS，不用单独引 `websockets` 库 |
| 前端 | **原生 JS（ES Modules，无构建步骤）+ ECharts** | 需求要求"别用重框架"；ECharts 自带深色主题、仪表盘、自适应容器，观感比 Chart.js 更"现代化"；vendor 文件本地化，不依赖 CDN |
| 样式 | 手写 CSS（CSS 变量 + Grid/Flex） | 深色主题优先、手机竖屏/宽屏自适应只需媒体查询，不需要 UI 库 |
| 配置 | **config.toml**（Python 3.11 内置 `tomllib`，3.10 用 `tomli`） | 需求指定；不搞数据库 |
| 密码持久化 | **`keyring` 库**（Windows 用凭据管理器，Linux 用 Secret Service） | 满足"可选持久化保存或不保存"，且明文不落盘、不进日志 |
| 桌面壳 | **Tauri v2** | 需求指定，比 Electron 轻 |
| 安卓壳 | **Capacitor**，目标 arm64-v8a（安卓 8.0+/64bit） | 需求指定；直接包 Web 层，采集层留在后端 |
| 打包 Web 版 | `pyinstaller`（可选）或直接 `python -m` 启动 | 第二阶段先不做，列在这里占位 |

**一个关键架构决策：采集方式选"远端 while 循环吐流"。**

两种实现里选第一种：连接建立后，在远端执行一段只读 shell 脚本，脚本内 `while` 循环每秒输出一行原始数据到 stdout，后端收流解析。理由：

- OpenWrt 上 Dropbear 每次 `exec` 新通道有开销，流式方案整条连接只有 1 个通道；
- 远端脚本只 `cat` /proc、/sys 文件，busybox sh 就能跑，对发行版零依赖；
- **差值计算（CPU 使用率、网速）放在后端 parser 里做**，远端脚本只吐原始计数器——脚本越简单越不容易在某个奇怪设备上翻车。

## 二、模块划分

### 采集层（backend/collector）

| 模块 | 职责 |
|---|---|
| `collector.py` | 维护 SSH 长连接；执行远端探针脚本；逐行读取 stdout；**指数退避重连**（1s→2s→4s…上限 30s）；向服务层广播"在线/离线"状态 |
| `remote_probe.sh` | 推送到远端执行的只读脚本：每秒输出一行 JSON 原始采样（见第四节）。所有字段独立 try，取不到就 null |
| `parser.py` | 有状态解析器：保存上一次采样，计算 CPU 使用率（/proc/stat 差值）、各网卡速率（/proc/net/dev 差值 ÷ 实际间隔）；输出最终指标 JSON |
| `credentials.py` | 凭据管理：Web 登录表单提交的用户名/密码 → 存内存；勾选"记住密码"→ 写系统密钥环；config.toml 可预置私钥路径或从环境变量读密码。**任何凭据不进日志** |

### 服务层（backend/app）

| 模块 | 职责 |
|---|---|
| `main.py` | FastAPI 入口：静态托管前端、HTTP 快照接口、WebSocket 推送、登录/登出接口、配置读写接口 |
| `config.py` | 读写 config.toml（采集间隔、告警阈值、SSH 主机/端口、要记住的连接参数）；配置变更热生效 |
| `alerts.py` | 阈值判定：温度>70℃、内存可用<10%、根分区可用<1G（阈值可配）；产出告警事件，前端据此变色+横幅 |
| `hub.py` | 广播器：collector 产出的指标 + 状态，推给所有已连接的 WebSocket 客户端 |

### 展示层（frontend）

| 模块 | 职责 |
|---|---|
| `login` 视图 | 主机/用户名/密码两个输入框 + "记住密码"复选框；连接中/失败状态提示 |
| `dashboard` 视图 | 顶部横幅（告警）、当前值大字卡片（CPU/内存/温度/网速/负载/磁盘/运行时间/发行版）、5 分钟折线图区 |
| `ws.js` | WebSocket 客户端：断线自动重连；**离线时保留最后一次数据，界面置灰显示"离线"角标，不清空** |
| `charts.js` | ECharts 封装：滚动窗口 5 分钟（300 点），统一深色主题 |
| `api.js` | 登录、快照、配置读写的 HTTP 封装 |

## 四、数据格式定义

### 4.1 远端探针原始采样（每秒 1 行 JSON，stdout）

差值类字段（CPU tick、网卡字节计数器）输出原始值，由后端 parser 计算速率。每项独立 try，失败即 `null`。

```json
{
  "ts": 1730000000.123,
  "cpu": {"total": 123456789, "idle": 98765432, "cores": 4},
  "load": [0.52, 0.41, 0.33],
  "mem": {"total_kb": 2048000, "available_kb": 1024000, "buffers_kb": 102400, "cached_kb": 204800},
  "temps": [{"zone": "thermal_zone0", "type": "x86_pkg_temp", "milli_c": 55000}],
  "disks": [{"fs": "/dev/sda1", "mount": "/", "total_kb": 10485760, "used_kb": 5242880, "avail_kb": 5242880}],
  "net": [{"iface": "eth0", "rx_bytes": 123456789, "tx_bytes": 9876543}],
  "os": {"pretty_name": "Debian GNU/Linux 12"},
  "uptime_s": 86400.5
}
```

字段缺失规则举例：KVM 虚拟机没有 thermal_zone → `"temps": null`；某个网卡计数器读不到 → 该 iface 条目省略。

### 4.2 后端算完推给前端的指标（WebSocket 帧 / HTTP 快照，同一结构）

```json
{
  "type": "metrics",
  "ts": 1730000000.123,
  "online": true,
  "host": "192.168.1.1",
  "os": "Debian GNU/Linux 12",
  "uptime_s": 86400,
  "cpu": {"usage_pct": 23.5, "cores": 4, "load": [0.52, 0.41, 0.33]},
  "mem": {"total_kb": 2048000, "available_kb": 1024000, "used_pct": 50.0},
  "temps": [{"zone": "thermal_zone0", "type": "x86_pkg_temp", "temp_c": 55.0}],
  "disks": [{"fs": "/dev/sda1", "mount": "/", "total_gb": 10.0, "avail_gb": 5.0, "used_pct": 50.0}],
  "net": [{"iface": "eth0", "rx_kbps": 120.5, "tx_kbps": 30.2}],
  "alerts": [{"item": "temp", "zone": "thermal_zone0", "value": 75.0, "threshold": 70, "msg": "温度过高"}]
}
```

任何字段取不到 → `null`，前端渲染 "—"。算速率需要的两次采样间隔不足（如刚重连）→ 该帧速率字段为 `null`，不输出 0 冒充真实值。

### 4.3 WebSocket 消息类型

| type | 方向 | 说明 |
|---|---|---|
| `metrics` | 服务端→前端 | 每秒一帧，结构见 4.2；`online: false` 时为最后一次缓存数据 + 状态标记 |
| `status` | 服务端→前端 | 连接状态变化（connecting / online / offline），前端显示角标 |
| `config` | 前端→服务端 | 第三阶段：修改告警阈值（也可走 HTTP PUT /api/config） |

### 4.4 HTTP 接口（首次加载 + 登录）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` | body: `{host, port, username, password, remember}`；后端建立 SSH 连接，成功返回快照；`remember=true` 时密码写系统密钥环，否则只存内存 |
| POST | `/api/logout` | 断开 SSH、清除内存凭据（密钥环中的按用户选择是否清除） |
| GET | `/api/snapshot` | 最近一次指标 + 连接状态 |
| GET | `/api/config` / PUT | 读取/修改阈值与采集参数（第三阶段） |

## 五、安全设计要点

- 密码三个来源，优先级：环境变量 `MONITOR_SSH_PASSWORD` > 系统密钥环 > 用户登录框输入（仅内存）。
- config.toml **不存密码**，只存 host/port/username/私钥路径/阈值；`.gitignore` 排除真实配置。
- 日志脱敏：任何日志语句禁止输出 password/private key。
- 远端只执行一段固定的只读探针脚本（`cat /proc/*`、`df -P -k`、`cat /sys/class/thermal/*`），无写操作、无 shell 拼接用户输入。

## 七、遗留决策点（默认按本文执行，可随时推翻）

1. **asyncssh vs paramiko**：默认 asyncssh；如果目标设备出现 Dropbear 兼容问题再降级 paramiko（接口已隔离在 `collector.py` 内，替换成本小）。
2. **ECharts vs Chart.js**：默认 ECharts（深色仪表观感更好，~300KB 本地文件对 Tauri/Capacitor 无压力）。
3. 安卓壳最低支持版本默认 Android 8.0（API 26），arm64-v8a 优先，兼容 armeabi-v7a 可选。
