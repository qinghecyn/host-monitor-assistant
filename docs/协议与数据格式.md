# 协议与数据格式定义

## 一、远端行协议（collect.sh → 本地解析器）

远端每 `interval_s` 秒输出**一行**，段用 `|` 分隔，条目用 `;` 分隔，字段用 `,` 分隔。
任一段采集失败则整段省略；解析器对该项置 `null`/`[]`。

```
T=<unix秒>
U=<uptime整秒>
L=<load1>,<load5>,<load15>
CPU=t:usr,nic,sys,idle,iow,irq,sirq,steal;0:...;1:...   累计 jiffies
MEM=<总KB>,<可用KB>,<BuffersKB>,<Cached+SReclaimableKB>
DSK=<挂载点>,<总KB>,<可用KB>,<累计读KB>,<累计写KB>,<块设备名>;...  beta2.5 新增第 6 字段
NET=<网卡>,<rx累计字节>,<tx累计字节>,<operstate>;...  beta2.3：全部接口（排除 lo）
TMP=<类型>,<毫摄氏度>;...
FAN=<名称>,<RPM>;...                                    beta2.1 风扇段，无 hwmon 风扇时省略
GPU=<名称>,<驱动>,<占用%>,<显存已用MiB>,<显存总MiB>,<温度℃>,<功耗W>;...  beta2.4 GPU 段，无显卡时省略
OS=<PRETTY_NAME 全文>
DKS=none | down | ok,<运行数>,<容器总数>                beta2.0 Docker 段
DKP=<id>,<名称>,<镜像>,<state>,<状态详情>;...            docker ps -a 的缓存快照
DKST=<id>,<cpu%>,<已用>/<上限>,<内存%>,<网络IO>,<块IO>;...  docker stats 的缓存快照
```

设计要点：

- **远端只吐累计值**（CPU jiffies、网卡字节），速率由本地两次采样差值计算，
  重连后首个差值帧为 `null`（不产出虚假尖峰）；计数器复位（负差值）同样置 `null`。
- 每行带 `T=` 时间戳，速率按实际间隔折算，避免远端 `sleep` 精度问题。
- `df -P -k` 无类型列，按设备名/挂载点排除伪文件系统；根分区 `/` 例外保留
  （OpenWrt 的 `/` 是 overlay），保证"根分区可用 < 1G"告警可用。
- **磁盘段（beta1.3）**：`DSK` 的第 4、5 字段是该挂载点对应块设备的累计读/写 KB
  （`/proc/diskstats` 扇区数 × 512 / 1024），旧 3 字段脚本仍兼容（速率按 0 处理）。
  解析端按相邻两帧差值算 `read_kbps` / `write_kbps`（单位 KB/s），前端再按用户选择
  显示 MiB/s 或 GiB/s。`overlay`、`tmpfs` 等没有独立块设备的挂载点读写量为 0。
- **磁盘设备名（beta2.5）**：第 6 字段取 `df -P -k` 的设备列（如 `/dev/sda1`、`/dev/mmcblk0p2`），
  解析为 JSON 的 `dev`。前端默认显示设备名，可切换回挂载点；老脚本（无第 6 字段）或
  `overlay`/`tmpfs` 等伪文件系统该字段为空，解析端回退为挂载点。多挂载点共用同一块设备时，
  各行会显示相同设备名且速率计数相同（沿用既有按挂载点取 `/proc/diskstats` 的口径）。
- **网络段（beta2.3）**：`NET` 输出 `/proc/net/dev` 里除 `lo` 外的**全部**接口，第 4 字段 `operstate`
  从 `/sys/class/net/<iface>/operstate` 读，读不到留空（旧脚本的 3 字段格式仍兼容）。
  所有累计字节必须用 `%.0f` 输出——busybox awk 的 `%d` 是 32 位有符号，超过 2^31 会变负数。
  解析端给每帧恰好一个接口标 `primary=true`（优先非 down 的真实接口，再按累计流量最大），
  前端大数字 / 折线图与 `server/store.py` 历史曲线统一使用这个标记，不各自取 `network[0]`。
- **Docker 段（beta2.0）**：没装 docker 的机器完全不输出 DK*（前端据此显示"未安装"）。
  `docker stats --no-stream` 采样要 1~2 秒，不能每秒都跑——脚本里按时间缓存：
  容器列表每 5s、资源占用每 30s 刷新一次，其余帧复用缓存值；
  刷新那一帧会变慢，但速率差值用帧内时间戳折算，不受影响。
  容器 ID 截断到 12 位作为 DKP↔DKST 的合并键；`docker ps` 最后一个字段
  （状态详情）里的逗号由解析端"末字段吞掉"处理，不会错位。
- **GPU 段（beta2.4）**：三家显卡统一成一个条目格式。NVIDIA 专有驱动优先
  `nvidia-smi --query-gpu=...`（名称/占用/显存/温度/功耗一步到位，`[N/A]` 置空）；
  AMD(amdgpu) / Intel(i915、xe) / nouveau 走 sysfs —— `device/gpu_busy_percent`、
  `device/mem_info_vram_*`（字节→MiB）、`device/hwmon/hwmon*/temp1_input`（毫度→℃）、
  `power1_average|power1_input`（微瓦→W）。名称优先 `product_name`，缺省
  「厂商 (cardN)」；某块卡一个有效读数都没有就不上报（过滤 virtio 虚拟卡），
  没有任何显卡则整段省略。数值缺失是空字段 → JSON `null`；显存两项齐全时
  解析端顺带算 `mem_percent`。90 天落库新增汇总指标 `gpu.busy_percent` /
  `gpu.mem_used_percent` / `gpu.temp_c`（多卡取最大）、`gpu.power_w`（取总和）。

## 二、JSON 数据帧（服务层 → 前端）

每秒一帧，WebSocket `{"type":"metrics","target":主机名,"data":帧}`；HTTP
`GET /api/snapshot` 返回 `{targets, thresholds, interval_s, data:{主机:{status, latest, history, alerts}}}`。

  "uptime_s": 86400,

## 三、WebSocket 消息

客户端 → 服务端：

```jsonc
{"type":"auth","token":"..."}   // 连接后 10 秒内必须发，否则关闭(4001)
{"type":"ping"}
```

服务端 → 客户端：

```jsonc
{"type":"hello",  "version":"beta2.3", "targets":["wsl"], "target_info":[...],
                  "thresholds":{...}, "probes":[...], "notify":{...}, "data":{...}}   // 鉴权后的完整快照
{"type":"metrics","target":"wsl","data":{帧}}                            // 每秒（帧含 docker/fans）
{"type":"status", "target":"wsl","state":"online|offline|connecting"}    // 断线不清空历史
{"type":"alert",  "target":"wsl","items":[{"kind":"temp|mem|disk","zone":"...","value":n,"threshold":n,"level":"high","text":"..."}]}
{"type":"probe",  "probes":[{name,type,host,port,state,ms,fails,detail,...}]}  // beta2.2：拨测状态变化时全量推送
{"type":"targets","targets":[{...目标信息...}]}   // beta0.1 新增：增删改服务器后广播，客户端应重取快照
{"type":"pong"}
```

## 四、HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/ping | 就绪探测，**无需鉴权**；桌面壳启动时轮询这个 |
| POST | /api/login | `{username,password}` → `{token}`；内存 token，24h |
| POST | /api/login/desktop | beta0.1：`{token}`（壳进程注入的一次性令牌）→ `{token}`，桌面版免登录 |
| GET | /api/snapshot | 鉴权（Bearer 或 ?token=），完整快照+历史 |
| GET | /api/config | 鉴权；返回脱敏配置（不含 SSH 密码） |
| PUT | /api/config | 鉴权；白名单字段更新并落盘，必要时自动重启采集器 |
| GET | /api/targets | beta0.1：服务器列表（含状态、`has_password`，**不含密码**） |
| POST | /api/targets | beta0.1：新增，body `{name, host, port, username, password?, private_key?, label?, note?}` |
| PUT | /api/targets/{name} | beta0.1：修改；密码字段留空 = 保持原密码 |
| DELETE | /api/targets/{name} | beta0.1：删除（同时停掉该目标的 SSH 长连接） |
| POST | /api/targets/test | beta0.1：试连，返回 `{ok, message, os, cores, latency_ms}`；只传 `name` 时复用已存密码 |
| GET | /api/history?host&metric&minutes | beta2.2：历史查询，降采样 ≤800 点，`{points:[[ts,v],...]}` |
| GET/POST/PUT/DELETE | /api/probes… | beta2.2：拨测 CRUD；POST/PUT 后热重载探针并广播 probe |
| POST | /api/notify/test | beta2.2：`{channel: serverchan\|telegram\|smtp\|webhook}` 发测试消息 |
| GET/POST | /api/service | beta2.2：Windows 服务状态 / `{action: install\|uninstall\|start\|stop}` |
| POST | /api/shutdown | beta0.1：停止服务进程（桌面版会让窗口一起退出） |

**错误约定**：`400` = 参数/校验不通过（`detail` 是给用户看的中文原因），
`401` = 未登录或 token 过期，`404` = 目标不存在，`404` 也用于"未启用桌面模式"。

## 五、config.toml

```toml
[server]   listen_host, listen_port
[auth]     username, password        # Web 登录；优先环境变量 MON_WEB_PASSWORD
[collect]  interval_s, history_minutes
[alerts]   temp_c, mem_available_percent, root_free_gb
[notify]   enabled, dedup_minutes, quiet_start, quiet_end,
           serverchan_key, telegram_token, telegram_chat,
           smtp_host, smtp_port, smtp_user, smtp_pass, smtp_to,
           webhook_url, heartbeat_minutes      # beta2.2 告警推送（凭据只写不读）
[history]  keep_days                            # beta2.2 落盘保留天数（7~365）
[targets.<名称>] host, port, username,
                 private_key | password | password_env,
                 host_key_policy = "autoadd" | "strict",
                 label, note                    # beta0.1：界面别名 / 备注
[probes.<名称>] type = "tcp" | "http" | "ping",
                host, port, path, expect,
                interval_s, timeout_s, fail_threshold   # beta2.2 服务拨测
```

写入规则（beta0.1）：

- 目标名只允许 `[A-Za-z0-9_-]{1,32}`，避免 `[targets.a.b]` 被解析成嵌套表；
- 写入是**原子操作**（临时文件 + `os.replace`），并保留 `config.toml.bak`；
- 界面里的增删改会立刻写回本文件并重建该目标的采集器，**不需要重启服务**；
- 文件顺序 = 界面里的服务器顺序（TOML 表顺序保留）。

SSH 密码优先级：目标 `password`（明文，不推荐）→ 环境变量（目标 `password_env`
或全局 `MON_PASSWORD`）→ 系统密钥环（keyring）。
