## 一、产品代码真 Bug（测试或实测抓住，已全部修复）

| # | Bug | 根因 | 怎么发现的 | 修复 |
|---|---|---|---|---|
| 1 | Docker 容器字段全丢，界面只剩一串 ID | collect.sh 里 `tr ',;|' ' '` 把 docker 自身的逗号分隔符也清洗掉了 | 用**假 docker 命令**做行为测试（5 组用例），第 1 组就抓出 | 清洗只针对 `; \|`，字段内逗号由解析端"末字段吞掉" |
| 2 | 没装 docker 的机器收不到"未安装"标记 | `docker_emit` 在未探测到 docker 时直接 return，整段消失 | 同上，用例 2 | 显式输出 `DKS=none` |
| 3 | 容器运行数/总数永远是 0/1 | awk 把 `;` 拼接的整行当成一条记录计数 | 同上，用例 1 的 `ok,0,2` 对不上 | 先 `tr ';' '\n'` 再计数 |
| 4 | 历史趋势降采样桶数溢出：max_points=10 返回 11 个点 | span/bucket 非整除时末尾多出一个桶 | 新写的单测抓出 | 桶下标 `min(idx, nb-1)` 钳位 |
| 5 | HTTP 拨测把"服务在应答"误判为宕 | urllib 对非 2xx 抛 HTTPError 异常，被当成连接失败 | e2e 用本地只收 POST 的假服务器实测抓出 | 捕获 HTTPError 作为有效响应（存活探测口径：有应答即活） |
| 6 | 拨测告警文案"拨测 拨测 xxx"重复前缀 | host 和 text 各带一次"拨测" | e2e 输出肉眼可见 | 文案职责拆开：host=通道类别，text=明细 |
| 7 | 历史趋势图 x 轴域跑飞：刻度跨了几个月，单点还不可见 | 单点数据时 Chart.js linear 轴自动撑到 0 起点；pointRadius=0 点不可见 | 浏览器截图验收抓出 | x 域手动钉在数据范围 ±4%；≤2 点时显示圆点 |
| 8 | 心跳/恢复通知出现"-0 分钟" | 时间差为负时直接格式化 | 单测输出肉眼可见 | `max(0, mins)` |

## 二、架构与兼容性坑（设计阶段没预见，真机/真环境暴露）

| # | 坑 | 根因 | 修复/规避 |
|---|---|---|---|
| 9 | 手机端内容顶到状态栏，和时钟电池叠在一起 | targetSdk 35 在 Android 15+ **强制 edge-to-edge**，WebView 画到系统栏底下 | MainActivity 按 WindowInsets 加顶部内边距 + 状态栏底色同主题（用户真机报告） |
| 10 | 手机升级换包后，原生修复生效但页面还是旧的 | 静态资源响应没带 Cache-Control，WebView 启发式缓存继续用旧 JS——**最隐蔽的一个**：一半新一半旧 | 后端静态资源统一 `Cache-Control: no-cache`（etag 协商，304 开销可忽略）（用户真机报告） |
| 11 | 全面屏左右侧滑返回无法"返回上一级" | 返回事件被壳统一写死成"收后台" | 壳先调页面 `__xmmHandleBack()`：面板开着先关面板，关无可关才收后台（用户真机报告） |
| 12 | 私钥路径提示是 Windows 路径 | 手机/桌面共用一套网页，占位符写死桌面习惯 | 前端按 UA 区分平台（用户真机报告） |
| 13 | Chaquopy 源码合并失败：`__init__.py` 撞名 | srcDir 是"目录内容平铺"语义，server/ 和 collector/ 两个空 `__init__.py` 落到同一路径 | 改为"项目根 srcDir + include 白名单" |
| 14 | pydantic-core 没有安卓轮子 | fastapi 新版强依赖 pydantic v2（Rust 扩展），Chaquopy 仓库没有构建 | 锁 `fastapi<0.116 + pydantic v1（纯 Python）`，手机端 Python 用 3.13（v1 兼容最好的版本） |
| 15 | 拨测配置改动后手机端不同步 | 设计取舍：拨测配置跟 config.toml 走，双端各自生效 | 记入文档；未成为 bug |

## 三、工具链与流程坑（环境问题，记入避坑清单）

| # | 坑 | 教训 |
|---|---|---|
| 16 | Android Studio 自带 JBR 是 JDK 25，Gradle 8.x 直接拒绝启动 | 构建文档明确 JDK 21 路径（Adoptium）；AGENTS.md 已记录 |

| 20 | e2e 重跑撞 10 分钟告警冷却 + 撞旧进程旧代码，出现"TIMEOUT 假失败" | 测试卫生：每轮 e2e 用全新数据目录 + 全新进程；AGENTS.md 已记录 |

**做对了的**：

1. **"打包前必须实测"** 立住了——#1/#2/#3 是假 docker 行为测试抓的，#5 是本地假服务器抓的，
   #9/#10/#11/#12 是真机报告的。四个模块没有一个是"编译通过就交付"的。
2. **AGENTS.md 交接机制生效**——三轮升级跨了多个会话，版本号 9 处清单、构建环境、
   用户规矩全部没有丢。
3. **e2e 全链路先行**——beta2.2 的 WebHook 本地接收器把推送管线一次验证到位，
   问题都死在了交付之前。

1. 版本号断言（test_e2e）连续三轮忘记同步——已从"记得改"升级为 AGENTS.md 的固定清单，
   但本质上应该把版本断言改成"从 VERSION 常量读取"，下一版顺手做掉。
2. 手机端每次改动都要 1.6G 模拟器重装才能验证——考虑保留一个常驻 AVD 或建一个
